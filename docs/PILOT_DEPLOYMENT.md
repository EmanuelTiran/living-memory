# פריסת פיילוט פרטי — Living Memory

מטרת הפריסה הזאת היא לאפשר למספר קטן של משפחות לבדוק את ליבת המוצר: הזמנה אישית, תיעוד בקול ובכתב, אישור מקורות, שאלות משפחתיות ותשובות שמפנות למקור. שכבת האווטאר מוסתרת בפיילוט אך נשארת בקוד וניתנת להפעלה מחדש במתג תכונה.

## מבנה הפריסה

יש להפעיל שירות Node יחיד שמגיש גם את ה־API וגם את קובצי React הבנויים. MongoDB נשאר מסד הנתונים. קובצי הקלטה ונכסים משפחתיים נשמרים בדיסק מתמשך שמחובר לשירות.

הפיילוט חייב לרוץ במופע אחד בלבד. תור העיבוד וקובצי המדיה הם מקומיים לתהליך ולדיסק, ולכן אין להפעיל כמה מופעים לפני מעבר לתור ולאחסון משותפים.

## משתני סביבה

העתיקו את `server/.env.production.example` להגדרות הסודיות של ספק האחסון, ואל תעלו קובץ `.env` אמיתי ל־Git.

בזמן בניית הלקוח הגדירו:

```text
VITE_PILOT_INVITE_ONLY=true
VITE_PILOT_AVATAR_ENABLED=false
```

בזמן הרצת השרת הגדירו לפחות:

```text
NODE_ENV=production
PILOT_INVITE_ONLY=true
PILOT_AVATAR_ENABLED=false
SERVE_CLIENT_BUILD=true
PERSISTENT_STORAGE_REQUIRED=true
TRUST_PROXY_HOPS=1
```

יש להשתמש ב־`ACCESS_TOKEN_SECRET` אקראי באורך 43 תווים לפחות, ב־MongoDB שאינו פתוח לרשת כולה, ובנתיבי אחסון מוחלטים על דיסק מתמשך. אין להגדיר מפתחות D‑ID בפיילוט הזה.

## Build והפעלה

פקודת הבנייה:

```bash
npm ci
npm run check
VITE_PILOT_INVITE_ONLY=true VITE_PILOT_AVATAR_ENABLED=false npm run build
```

פקודת ההפעלה:

```bash
npm start
```

השרת מגיש את `client/dist` מאותו דומיין. כך עוגיות ההתחברות נשארות באותו מקור ואין צורך ב־CORS לפיילוט.

## בדיקות בריאות

- `GET /api/health` הוא liveness: התהליך פועל.
- `GET /api/ready` הוא readiness: החיבור למסד והגישה לאחסון תקינים.

יש להגדיר את בדיקת הבריאות של ספק האחסון ל־`/api/ready`. תשובת `503` אומרת שאין לשלוח משתמשים למופע עד שהמסד והדיסק זמינים.

## הצטרפות משפחה

1. בעל הארכיון נכנס לחשבון קיים.
2. מתוך מסך הזיכרון הוא פותח את ניהול המשפחה ויוצר הזמנה לכתובת אימייל מדויקת.
3. בן המשפחה פותח את קישור ההזמנה האישי.
4. אם אין לו חשבון, קישור ההזמנה מאפשר לפתוח חשבון. פתיחה ישירה של `/register` חסומה.
5. לאחר הכניסה הוא מאשר את תנאי ההשתתפות וחוזר לארכיון שהוזמן אליו.

קישור ההזמנה הוא סוד זמני. אין לפרסם אותו בקבוצה או להעביר אותו לאדם אחר.

## בדיקת עשן לאחר פריסה

1. פתחו את העמוד הראשי בחלון פרטי וודאו שמופיעה רק כניסה לפיילוט הפרטי.
2. פתחו `/register` ישירות וודאו שמופיעה הודעה שההרשמה בהזמנה בלבד.
3. התחברו כבעל הארכיון וצרו הזמנה לכתובת בדיקה שנייה.
4. פתחו את ההזמנה בחלון פרטי, צרו חשבון והצטרפו.
5. הקליטו תיעוד קצר, בדקו את התמלול ואשרו אותו.
6. שאלו מחשבון המשפחה שאלה שהתשובה עליה קיימת בתיעוד, וודאו שמופיע מקור מאושר.
7. רעננו את הדף וודאו שהתוכן וההרשאות נשמרו.
8. וודאו שאין במסכי הפרופיל והשיחה אפשרות אווטאר.
9. בדקו ש־`/api/ready` מחזיר `200`.

## גיבוי והגבלת סיכון

- הפעילו גיבוי אוטומטי ל־MongoDB ולדיסק המדיה.
- בדקו שחזור לפני הכנסת חומר משפחתי שאין לו עותק אחר.
- התחילו בשתיים או שלוש משפחות, לא בקישור ציבורי.
- גבו תשלום רק לאחר שהמשתמש ראה את תנאי הפיילוט וההחזר.
- אל תפעילו מחדש אווטאר לפני החלטה נפרדת על חוויית המשתמש, הסכמה, פרטיות ועלויות ספק.
